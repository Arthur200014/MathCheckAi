# MathCheck AI — Stage 2.9.7.9

Рабочая сборка ЕГЭ №13 с единым пользовательским потоком **«одно фото → подтверждение условия и решения → проверка → отчёт»**.

## Быстрый запуск на Mac

Первый запуск после клонирования/первого `git pull`:

```bash
bash setup.sh
bash run.sh
```

Дальше для получения новой версии из GitHub:

```bash
bash update.sh
```

А для обычного запуска:

```bash
bash run.sh
```

`setup.sh` и `update.sh` автоматически создают чистый `.venv` и устанавливают зависимости. Локальные настройки Ollama хранятся в `.env.local`; если файла нет, он автоматически создаётся из `.env.example`. `.env.local`, база SQLite и локальные отчёты не отправляются в GitHub.

## Основной пользовательский поток

1. Открыть `http://127.0.0.1:8000/`.
2. Указать только ID ученика.
3. Загрузить одно PNG/JPG/WEBP, где видны условие и решение.
4. Vision за один проход пытается извлечь отдельно условие и решение ученика.
5. Если Vision не выделил условие отдельно, но первая видимая строка решения — исходное уравнение пункта а, система использует только эту строку как редактируемый черновик условия. Пункт б и интервал никогда не придумываются автоматически.
6. На странице рядом со сканом появляются два редактируемых поля: **«Условие задания»** и **«Решение ученика»**.
7. Пользователь исправляет OCR и дополняет условие, если часть задания не попала в кадр.
8. Перед запуском Solver выполняется детерминированная preflight-проверка условия №13: должны присутствовать уравнение пункта а и интервал пункта б.
9. Если интервала нет, проверка не запускается и пользователь получает просьбу дополнить поле условия. Никакой LLM не угадывает отсутствующий интервал.
10. После полного подтверждения `confirmed_task_statement` идёт в Solver/reference verifier, а `confirmed_transcript` — в source-locked student grading.
11. На странице показываются балл, комментарии, шаги, правильный ответ и эталонная окружность.
12. Внизу остаются OCR JSON и финальный JSON с кнопками копирования для диагностики.

## Важные инварианты

- Отдельно вводить условие до сканирования не нужно.
- Условие и решение извлекаются одним Vision-вызовом из одного изображения.
- Vision-результат всегда является черновиком и никогда не идёт прямо в оценивание.
- Человек всегда подтверждает и условие, и решение.
- Система не восстанавливает отсутствующий пункт б по памяти и не придумывает интервал.
- Неполное условие №13 блокируется до Solver, поэтому отсутствующие данные не могут быть галлюцинированы моделью.
- После подтверждения источники истины: `confirmed_task_statement` и `confirmed_transcript`.
- Source-lock не позволяет Grader/Reviewer подменять решение ученика эталоном.
- Single-pass Grader/Reviewer, deterministic score и activity-aware Ollama transport сохранены.
- UI не использует внешние JS/CSS-библиотеки.

Swagger: `http://127.0.0.1:8000/docs`.

## Stage 2.9.7.8 — human-readable confirmation editor

Human confirmation no longer exposes raw OCR LaTeX such as `\\frac`, `\\sqrt`, `\\pi`, or literal `\\n`. The browser receives presentation-only fields `display_task_statement` and `display_transcript` and shows ordinary Unicode mathematics (`π`, `√`, `≤`, `∈ ℤ`, real line breaks).

The raw OCR output is still preserved unchanged in the technical JSON at the bottom of the page. The text edited by the human becomes the authoritative `confirmed_task_statement` / `confirmed_transcript`; the existing tolerant parsers accept this human-readable notation directly.

## Stage 2.9.7.9 — task preflight

- Если Vision оставил условие пустым, исходное уравнение может быть взято только из реально видимой первой строки решения как черновик для человека.
- Для `ege_13` подтверждённое условие обязано содержать уравнение и интервал вида `[a; b]`.
- Если интервал отсутствует, API возвращает понятную ошибку до запуска Solver/Grader/Reviewer и сохраняет pending-состояние, чтобы пользователь мог исправить поле и повторить подтверждение.
