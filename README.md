# MathCheck AI — Stage 2.9.7.12

Рабочая сборка ЕГЭ №13 с пользовательским потоком **«одно фото решения → подтверждение уравнения, интервала и текста решения → проверка → компактный отчёт»**.

## Быстрый запуск на Mac

Первый запуск после клонирования/первого `git pull`:

```bash
bash setup.sh
bash run.sh
```

Получить новую версию из GitHub:

```bash
bash update.sh
```

Обычный запуск:

```bash
bash run.sh
```

`setup.sh` и `update.sh` создают чистый `.venv` и устанавливают зависимости. Локальные настройки Ollama хранятся в `.env.local`; база SQLite и локальные отчёты не отправляются в GitHub.

## Основной поток №13

1. Открыть `http://127.0.0.1:8000/`.
2. Указать ID ученика.
3. Загрузить фото решения ученика. Полное печатное условие на фото не требуется.
4. Vision транскрибирует работу ученика.
5. Исходное уравнение автоматически берётся из первой видимой строки решения, где ученик переписал задание.
6. Если на фото явно записан интервал пункта б, он подставляется как черновик. Если интервала нет, поле остаётся пустым — система его не придумывает.
7. Пользователь подтверждает три поля: **исходное уравнение**, **интервал пункта б**, **решение ученика**.
8. Только после этого сервер строит полное `task_statement` и запускает Solver → deterministic verifier → Grader → Reviewer.
9. На выходе показываются итоговый балл, короткое объяснение ошибки, разбор шагов, правильный ответ и эталонная окружность.
10. Внизу остаются OCR JSON и финальный JSON для диагностики.

## Математический ввод

LaTeX вводить не нужно. Поддерживаются обычные варианты:

- `π/2` или `pi/2`;
- `√2` или `sqrt(2)`;
- `x²` или `x^2`;
- `2πn` или `2*pi*n`;
- `n∈ℤ`.

На странице одна общая математическая панель с `π`, `√`, `²`, `³`, `±`, `∈ℤ`, `[`, `]`, `;`. Символ вставляется в поле, которое пользователь редактирует сейчас.

Интервал можно написать просто так:

```text
-3pi; -3pi/2
```

Сайт сам обернёт его в квадратные скобки.

## Пользовательский отчёт

- В интерфейсе нет технических статусов `REVIEWED`, `correct`, `incorrect`: пользователю показываются русские подписи **«Итоговый балл»**, **«Верно»**, **«Ошибка»**, **«Проверить»**.
- Если пункт б в подтверждённой работе отсутствует, отчёт пишет **«Пункт б не выполнялся»**.
- Правильный ответ показывается школьной записью, а не служебной формой SymPy. Например:

```text
x = π/2 + 2πn, n ∈ ℤ
x = -π/4 + 2πn, n ∈ ℤ
x = -3π/4 + 2πn, n ∈ ℤ
```

вместо `π(4n+1)/2`, `π(8n+5)/4` и подобных технически эквивалентных, но неудобных форм.
- У каждого ошибочного шага отчёт теперь показывает не только причину, но и конкретное исправление. Для ошибки периода, например: **«Неверный период. Правильно: x = π/2 + 2πn, n ∈ ℤ»**.
- Для неверного ответа пункта б рядом показывается правильный набор корней.
- Если точное исправление текущей строки нельзя восстановить детерминированно, показывается ближайший следующий проверенный правильный шаг, а не абстрактная фраза.
- Слева располагаются итог и разбор решения, справа — эталонная тригонометрическая окружность.
- На окружности жёлтым выделен правильный интервал отбора, зелёным — правильные корни.

## Важные инварианты

- OCR всегда является черновиком и никогда не идёт прямо в оценивание.
- Источник истины после подтверждения: `confirmed_task_equation`, `confirmed_interval`, `confirmed_transcript`.
- Отсутствующий интервал никогда не угадывается моделью.
- Если интервал не найден на фото, его вводит человек перед запуском Solver.
- Source-lock не позволяет Grader/Reviewer подменять решение ученика эталоном.
- Grader и Reviewer работают single-pass без retry.
- Итоговый балл считает deterministic rubric.
- Изображение отправляется в Vision в исходном качестве без resize/recompress.

Swagger: `http://127.0.0.1:8000/docs`.

## Stage 2.9.7.12 — school-format answers + corrections

- Эталонные семейства решений приводятся к привычному школьному виду с простым свободным углом и периодом.
- Эквивалентные углы нормализуются к коротким представителям, например `5π/4 → -3π/4`, если период `2π`.
- Ошибочный шаг получает поле `correction` и конкретную строку **«Правильно: …»**.
- Для ошибочного общего решения выбирается соответствующее эталонное семейство по тому же базовому корню.
- Для ошибки отбора корней показывается проверенный эталонный набор.
- Добавлены regression-тесты на формат ответа и коррекцию неверного периода.
