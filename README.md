# MathCheck AI — ЕГЭ №13

Текущий пользовательский поток: **одно фото решения → подтверждение распознанного текста → проверка → компактный экспертный отчёт**.

## Запуск на Mac

Первый запуск:

```bash
bash setup.sh
bash run.sh
```

Получить свежие изменения из GitHub:

```bash
bash update.sh
```

Обычный запуск:

```bash
bash run.sh
```

Интерфейс: `http://127.0.0.1:8000/`.

## Как работает №13

1. Пользователь загружает фото работы ученика.
2. Vision за один проход переписывает видимую работу.
3. Исходное уравнение берётся из первой строки решения ученика.
4. Интервал пункта б берётся либо из явно записанного отрезка, либо из видимых неравенств отбора корней вида `a ≤ выражение ≤ b`. Если достоверно восстановить интервал нельзя, он остаётся пустым и вводится человеком.
5. Пользователь подтверждает три поля: исходное уравнение, интервал пункта б и полный текст решения.
6. Только подтверждённые данные идут в Solver → deterministic verifier → Grader → Reviewer.
7. Итоговый балл рассчитывается детерминированным rubric-слоем.

## Математический ввод

LaTeX вводить не требуется. Поддерживаются привычные записи:

- `π/2` или `pi/2`;
- `√2` или `sqrt(2)`;
- `x²` или `x^2`;
- `2πn` или `2*pi*n`;
- `n∈ℤ`.

На странице одна общая панель символов `π`, `√`, `²`, `³`, `±`, `∈ℤ`, `[`, `]`, `;`. Символ вставляется в активное поле.

## Пользовательский отчёт

Отчёт больше не является длинным списком шагов с зелёными и красными статусами.

В нём показываются:

- итоговый балл;
- короткий итог по пунктам а и б;
- **ровно тот подтверждённый текст решения**, который пользователь видел и редактировал перед проверкой;
- несколько кратких экспертных комментариев только по реальным ошибкам;
- конкретное исправление, когда оно детерминированно известно;
- правильный ответ в школьной записи;
- справа — правильный отбор корней на тригонометрической окружности.

Пример комментария:

```text
Неверный период в общем решении.
В работе: x = π/2 + πn, n ∈ ℤ
Правильно: x = π/2 + 2πn, n ∈ ℤ
```

Для пункта б отчёт отдельно показывает лишние и пропущенные корни, если они есть.

## Почему больше нет ложной ошибки на ветвях

Раньше промежуточный checker пытался сравнивать почти каждую строку решения с исходным уравнением как будто каждая строка обязана быть ему полностью эквивалентна. Это логически неверно после разложения произведения на множители: например, строки `sin x - 1 = 0` и `2 sin x + √2 = 0` — отдельные ветви, и каждая из них по отдельности не эквивалентна всему исходному уравнению.

Теперь deterministic reasoning-слой работает по правилу **«помечать ошибкой только то, что действительно доказано неверным»**:

- полная эквивалентность отмечается только если она доказана символически;
- корректная ветвь произведения распознаётся как ветвь, а не как «неэквивалентная ошибка»;
- если эквивалентность не удалось доказать, это само по себе не превращается в красный вердикт;
- семейства общего решения и корни пункта б по-прежнему проверяются детерминированно.

## Важные инварианты

- OCR всегда является черновиком.
- Источник истины после подтверждения: `confirmed_task_equation`, `confirmed_interval`, `confirmed_transcript`.
- Интервал не восстанавливается из правильного ответа или эталонных корней.
- Source-lock не позволяет Grader/Reviewer подменять решение ученика эталоном.
- Grader и Reviewer работают single-pass без retry.
- Изображение отправляется в Vision в исходном качестве без resize/recompress.
- Законченные результаты сохраняются в истории браузера при загрузке следующей работы.
