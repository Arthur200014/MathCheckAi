# MathCheck AI — ЕГЭ №13

Локальная мультиагентная система предварительной проверки письменного решения задания ЕГЭ №13 по фотографии.

Текущий поток: **1–8 фото одной работы → один Vision-проход → ручное подтверждение OCR → preflight → Solver → SymPy/reference verifier → Grader → Reviewer → компактный экспертный отчёт**.

## Быстрый запуск на Mac

Первый запуск:

```bash
bash setup.sh
bash run.sh
```

Получить свежие изменения:

```bash
bash update.sh
bash run.sh
```

Интерфейс: `http://127.0.0.1:8000/`  
Swagger: `http://127.0.0.1:8000/docs`

## Что делает система

1. Пользователь выбирает от 1 до 8 фотографий одной работы.
2. Для одного фото Vision получает исходные байты. Для нескольких страниц сервер собирает их в один упорядоченный лист и делает один Vision-вызов вместо N последовательных вызовов.
3. OCR является только черновиком. Пользователь видит исходные фото и редактирует три поля: исходное уравнение, интервал пункта б, полный текст решения ученика.
4. Перед LLM-проверкой запускается детерминированный preflight №13. Неоднозначная запись, сломанные скобки, плохой интервал и другие структурные проблемы возвращают пользователя в тот же редактор; Solver ещё не запускается.
5. После успешного подтверждения Solver строит независимый эталон.
6. Быстрый deterministic/SymPy verifier независимо проверяет семейства решений и корни на заданном отрезке.
7. Grader сопоставляет подтверждённую работу с проверенным эталоном и критериями.
8. Reviewer делает single-pass аудит непротиворечивости; детерминированный балл для него неизменяем.
9. Формируется отчёт, правильный ответ/окружность и история проверки.

## Четыре агента

- **Vision Agent** — читает фото, но не выставляет балл.
- **Solver Agent** — решает подтверждённое задание независимо от ответа ученика.
- **Grader Agent** — проверяет подтверждённый текст ученика по критериям и verified reference.
- **Reviewer Agent** — проверяет непротиворечивость результата и добавляет advisory при сомнениях.

Preflight, SymPy verifier, rubric score, отрисовка окружности, report builder и SQLite — детерминированные tools/components, а не дополнительные агенты.

## Источник истины

После подтверждения используются только:

- `confirmed_task_equation`;
- `confirmed_interval`;
- `confirmed_transcript`.

Vision не может автоматически исправить математику ученика. Интервал не восстанавливается из правильного ответа. Source-lock не позволяет Grader/Reviewer подменить решение ученика эталоном.

## Математический ввод

LaTeX вводить не требуется. Поддерживаются привычные записи:

- `π/2` или `pi/2`;
- `√2` или `sqrt(2)`;
- `x²` или `x^2`;
- `2πn` или `2*pi*n`;
- `n∈ℤ`.

Неоднозначные OCR-конструкции вроде `sin x (x+π)` preflight не пропускает: человек должен явно оставить `sin(x+π)` либо запись умножения.

## Отчёт

Пользователь видит:

- итоговый балл;
- краткий итог по пунктам а и б;
- ровно тот подтверждённый текст решения, который был в редакторе;
- несколько конкретных экспертных комментариев по доказанным ошибкам;
- исправление, если оно детерминированно известно;
- правильный ответ в школьной записи;
- правильный отбор корней на тригонометрической окружности;
- время каждого этапа проверки.

## Скорость и telemetry

В UI отдельно измеряются Vision, preflight, Solver, reference verifier, Grader, Reviewer, сборка отчёта и сохранение.

Ollama используется через streaming NDJSON. Частичный JSON при таймауте не принимается как ответ. Grader и Reviewer работают без автоматических retry-вызовов.

Локальные LLM-вызовы пишутся в JSONL, для медленных вызовов создаётся alert.

## Eval и сравнение 3 LLM

Экспертный benchmark описан в `evals/README.md`.

Подготовка 12 сбалансированных кейсов (4×2 балла, 4×1, 4×0):

```bash
pip install -r requirements-eval.txt
python evals/prepare_ege13_images.py
```

Быстрая проверка одного кейса на основной модели:

```bash
python evals/run_ege13_benchmark.py --limit 1 --models qwen3-vl:4b-instruct
```

Финальный одинаковый прогон по трём моделям:

```bash
python evals/run_ege13_benchmark.py
```

Результаты сохраняются как JSON/CSV/Markdown с score accuracy, latency, manual-review rate и дополнительными метриками.

## Docker

Agent App можно поднять в Docker, а Ollama оставить нативно на macOS для локального ускорения:

```bash
docker compose up --build
```

Docker запускает тот же `src.run_app:app`, что и обычный локальный UI. SQLite/reports вынесены в локальные volume-папки `data/` и `reports/`.

## Ключевые ограничения MVP

- Только ЕГЭ №13.
- OCR всегда подтверждается человеком перед математической оценкой.
- Student diagram Vision-проверка не запускается в runtime MVP ради latency; эталонная окружность строится детерминированно.
- Итог — предварительная автоматизированная проверка для преподавателя, а не официальный эксперт ЕГЭ.
