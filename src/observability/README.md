# Observability

В проекте есть четыре части наблюдаемости: логи, метрики, трейсы и алерты.

## Логи

LLM-вызовы пишутся в `llm_calls.jsonl`.

Там можно увидеть:

- модель;
- агент;
- время работы;
- токены;
- done reason;
- ошибки и timeout.

## Метрики

В `ReviewState` и сохранённых review есть время основных этапов. Из SQLite можно получить общую статистику по успешным проверкам, ошибкам, ручной проверке и среднему времени агентов.

## Трейсы

Каждый этап LangGraph пишет span в `traces.jsonl`.

Для span сохраняются:

- `trace_id`, обычно это `review_id`;
- `span_id`;
- этап;
- время старта;
- время окончания;
- длительность;
- статус;
- текст ошибки, если этап завершился с ошибкой.

По одному `trace_id` можно собрать весь путь одной проверки от Vision до сохранения отчёта.

## Алерты

Если LLM-вызов дольше порога `MATHCHECK_SLOW_AGENT_SECONDS`, событие попадает в `alerts.jsonl` как `slow_llm_call`.

По умолчанию порог равен 120 секундам.

## Где лежат файлы

Путь задаётся переменной `MATHCHECK_OBS_DIR`.

Если переменная не задана, используется временная папка ОС:

```text
.../mathcheck-ai/observability/
  llm_calls.jsonl
  traces.jsonl
  alerts.jsonl
```

## Почему не LangSmith или Langfuse

Оба варианта рассматривались. Они удобнее для больших команд и дают красивый интерфейс для трейсов.

Для текущего локального MVP выбран простой JSONL-стек по двум причинам:

1. проект должен работать без внешнего сервиса и ключей;
2. нам достаточно видеть последовательность этапов, время, модель и ошибки.

При дальнейшем развитии можно отправлять те же события в Langfuse, LangSmith или OpenTelemetry. Формат локальных span для этого уже содержит основные поля.
