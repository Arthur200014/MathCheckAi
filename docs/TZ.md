# ТЗ на MathCheck AI

## 1. Что делаем

MathCheck AI проверяет решение задания ЕГЭ №13 по фотографии. Это не замена эксперта. Система должна подготовить понятный предварительный разбор, а спорные места отправить на ручную проверку.

На текущем этапе поддерживается только задание №13.

## 2. Кто пользуется

Основной пользователь - преподаватель или проверяющий.

Он загружает одну или несколько фотографий одной работы, проверяет распознанный текст и после этого получает итоговый отчёт.

## 3. Что приходит на вход

Обязательные данные:

- тип задания `ege_13`;
- одна или несколько фотографий решения;
- идентификатор проверки;
- идентификатор ученика.

После OCR пользователь подтверждает:

- условие;
- отрезок для пункта б);
- текст решения ученика.

До подтверждения математическая проверка не запускается.

## 4. Что должно быть на выходе

Система возвращает:

- балл от 0 до 2;
- статус пункта а);
- статус пункта б);
- найденные ошибки;
- правильный ответ;
- комментарий для преподавателя;
- признак ручной проверки, если данных не хватает;
- время работы основных этапов.

## 5. Агенты

В системе четыре основных LLM-агента.

### Vision Agent

Читает фотографию и делает транскрипцию. Не решает задачу и не исправляет ученика.

### Solver Agent

Решает подтверждённое условие независимо от решения ученика. Получает только условие, поэтому не может подгонять ответ под работу.

### Grader Agent

Сравнивает подтверждённое решение ученика с проверенным эталоном и критериями ЕГЭ №13.

### Reviewer Agent

Проверяет, что итог Grader не противоречит данным, критериям и результатам детерминированных проверок.

## 6. Детерминированные части

Не всё передаётся LLM. В проекте отдельно работают:

- parser школьной записи;
- preflight перед математической проверкой;
- SymPy/reference verifier;
- проверка семейств корней;
- проверка корней на отрезке;
- rubric для итогового балла;
- report builder;
- SQLite persistence.

LLM не является единственным источником итоговой оценки.

## 7. Основной flow

```text
Фото
 -> Vision Agent
 -> подтверждение человеком
 -> preflight
 -> Solver Agent
 -> Reference Verifier
 -> Grader Agent
 -> Reviewer Agent
 -> отчёт
 -> сохранение результата
```

Если OCR не подтверждён, flow останавливается. Если эталон не прошёл verifier, система не должна выдавать его как проверенный ответ.

## 8. Требования к качеству

Система должна:

- не менять решение ученика без подтверждения человека;
- не придумывать отсутствующие шаги решения;
- отделять OCR-ошибку от математической ошибки;
- возвращать структурированный результат;
- сохранять историю проверок;
- фиксировать время и ошибки по этапам;
- при сомнении отмечать необходимость ручной проверки.

## 9. Ограничения MVP

- поддерживается только ЕГЭ №13;
- ученическая тригонометрическая окружность не оценивается;
- пункт б) проверяется по подтверждённой записи выбранных корней;
- локальные Vision-модели медленные и могут ошибаться на рукописной математике;
- human confirmation обязателен для фото.

## 10. Среда запуска

Основной стек:

- Python 3.12;
- FastAPI;
- LangGraph;
- Ollama;
- SymPy;
- SQLite;
- Docker.

Приложение можно запускать локально. Для сдаваемого варианта Agent App запускается в Docker, а Ollama может работать на host macOS.

## 11. Критерии готовности

MVP считается готовым, если:

1. фото проходит через Vision;
2. пользователь может исправить OCR;
3. без подтверждения Solver не запускается;
4. Solver строит эталон;
5. verifier проверяет эталон;
6. Grader выставляет оценку по критериям;
7. Reviewer проверяет итог;
8. отчёт показывается пользователю;
9. результат сохраняется;
10. eval-набор можно запустить отдельной командой;
11. есть логи, метрики, трейсы и алерты для основных этапов.
